# 성능 감사

대상: `$ARGUMENTS` (비었으면 `src/` 전체). 기준은 CLAUDE.md 2절 '성능'과 3절 불변식 1, 2다.

## 원칙
- 고칠 것은 **실제 부하에서 일어나고, 일어나면 해가 큰** 결함뿐이다. 둘 다 증명해야 한다.
- 결함 0건은 정상 결과다. 건수는 평가하지 않는다. 가장 나쁜 결과는 증명하지 못한 후보를 고치는 것이다. 측정되지 않는 개선은 코드만 복잡하게 하고 다음 감사의 잡음이 된다.
- 증명 책임은 후보 쪽에 있다. "느릴 것 같다", "더 빠를 것이다", "많아지면"은 근거가 아니다. 근거는 빈도, 상한 N, 열어 본 비용, 측정이다.
- 후보는 넓게 모으고 결함은 좁게 정한다. 검사를 얕게 하라는 뜻이 아니다.
- CLAUDE.md 2절 규칙을 어긴 것이라도 등급이 경미면 이 감사에서는 고치지 않고 '경미'에 보고만 한다.

## 결함의 정의
다섯 조건을 모두 증명한 것만 결함이다.

1. **빈도**: 그 경로가 실제로 도는 빈도(틱마다, 플레이어마다 틱마다, 패킷마다, 청크 로드마다, 접속마다)를 호출하는 쪽을 따라가 확인한다. 이름이나 모듈 위치로 핫패스라고 정하지 않는다.
2. **규모**: 비용을 정하는 변수(플레이어, 엔티티, 청크, 월드, 큐 길이, 입력 크기)와 그 상한을 숫자로 정한다. 상한은 설정 범위(`.claude/docs/config.md`), 큐와 입력 예산(`.claude/docs/architecture.md`, `.claude/docs/network.md`, `.claude/docs/protocol.md`), 문서의 측정 한계에서 가져온다. 근거 없는 큰 N으로 비용을 부풀리지 않는다.
3. **비용**: 경로가 부르는 함수를 의존성까지 열어 실제 비용(할당, 복사, 순회, 해시, 잠금, 시스템 호출)을 센다. 열어 보지 않은 호출은 싸다고도 비싸다고도 하지 않는다.
4. **해**: 아래 등급표의 치명이나 중대에 닿는다.
5. **증거**: 등급표의 증거 칸.

## 등급
| 등급 | 결과 | 증거 |
|---|---|---|
| 치명 | 누수: 정상 운영 반복(접속·종료, 월드 로드·언로드, 엔티티·창·작업·타이머 생성과 제거, 장시간 가동)에서 표·큐·캐시·등록이 줄지 않고 늘어남 | 반복 뒤 개수가 시작 값으로 돌아오지 않는 시험(`src/tick/tests/leak.rs` 방식)이 지금 실패 |
| 치명 | 블로킹: 틱 스레드나 tokio 워커가 디스크 I/O, 잠금·채널 대기, sleep, 동기 네트워크로 멈춤 | 블로킹 호출까지의 경로 `파일:줄`과 그 호출이 블로킹인 근거(의존성 코드) |
| 치명 | 증폭: 외부 입력 하나가 입력 예산에 비례하지 않는 비용(전체 순회, 제곱, 큰 할당)을 일으켜 한 틱이 틱 예산(`tick::TICK`)을 넘거나 공유 워커를 그만큼 붙잡음 | release 측정: 그 입력을 넣은 틱이나 작업의 비용 |
| 중대 | 병목: 상한 부하에서 매 틱 도는 경로가 틱 예산의 2% 이상이고, 구조(색인, 미리 계산, 틱 밖으로 옮기기, 할당 재사용)로 그 대부분을 없앨 수 있음 | release 측정 전후 |
| 중대 | 스파이크: 주기 작업이 한 틱에 몰리거나, 틱 안의 큰 해제·지연 초기화·재할당 때문에 그 틱만 예산을 넘김 | release 측정의 최대·p99 틱 전후 |
| 경미 | 그 밖(상수 배 개선, 드문 경로, 상한 부하에서 틱 예산의 2% 미만) | 고치지 않는다 |

## 후보가 아닌 것
- 시작, 종료, 명령, 드문 이벤트 경로의 할당과 선형 검색. 한 번 실행이 틱 예산을 넘을 때만 후보다.
- 상한과 해제 시점이 있는 컬렉션과 큐. 상한까지 차는 것은 누수가 아니다.
- 설계로 정한 것: 틱 사이 대기의 `sleep`, 저장 스레드와 블로킹 풀의 블로킹, 네트워크 워커의 코덱·압축·암호화, `.claude/docs/`에 측정과 이유가 적힌 선택과 '알려진 한계와 위험'. 그 측정이나 이유가 지금 코드에서 틀렸음을 보일 때만 후보다.
- `cargo xtask check`가 이미 막는 것(`.clippy.toml` 금지 목록, `clone_on_ref_ptr` 등). 단 `#[expect]`로 푼 자리는 그 이유가 사실인지가 후보다.
- 확장 지점의 `dyn`, 컴파일러가 없애는 비용(작은 `Copy`, 이동, 작은 함수 호출), 이미 용량을 잡은 컨테이너.
- 시험 코드와 생성 파일 자체(생성 코드의 비용은 생성기에서 고친다).
- 측정 없는 "더 빠를 것 같다", 마이크로 최적화, 틱 밖 경로의 상수 배 개선.
- 같은 원인의 여러 자리는 한 건이다.

## 순서
1. **읽기**: `.claude/rules/architecture.md`, `.claude/docs/architecture.md`('스레드와 큐', '틱', '알려진 한계와 위험'), 대상 주제의 rules와 docs.
2. **측정부터**: 틱 측정 시험(`.claude/docs/testing.md`의 측정 예)이 대상 경로를 덮으면 release로 먼저 돌려 단계별 실제 비용을 보고 큰 몫부터 본다. 측정 규칙은 `.claude/rules/testing.md`를 따른다.
3. **수집**: 코드 모양이 아니라 빈도와 자원에서 출발한다.
   - 후보는 빈도, 상한 N, 비용 식(예: 틱마다 N_player × N_entity 비교)을 채울 수 있을 때만 적는다. 못 채우면 그 자리에서 버린다.
   - 대상이 크면 틱 단계, 네트워크·세션, 저장, 청크·조명 같은 묶음으로 나눠 파일을 고치지 않는 서브에이전트에 수집만 맡긴다. 이 파일을 읽게 하고 후보마다 빈도, N, 비용 식, `파일:줄`을 돌려받는다. 판정은 직접 한다.
4. **반증**: 후보마다 "이것이 결함이 아니라면 무엇이 비용을 막고 있는가"를 먼저 묻는다: 상한, 캐시, 이미 있는 색인, 엇갈린 주기, 빈 경우 건너뛰기, `slow-empty-worlds` 같은 설정, 호출 빈도가 생각보다 낮음. 막는 것이 있으면 기각한다.
5. **재현**: 등급표의 증거를 만든다. 누수는 실패하는 반복 시험, 증폭·병목·스파이크는 상한 N에서의 release 측정(`#[ignore = "measurement"]`)이다. 측정에서 문턱을 넘지 않으면 기각한다.
6. **독립 검토**: 재현된 후보마다 새 서브에이전트에 주장(빈도, N, 비용 식, 결과)과 측정·시험만 주고, 찾은 과정은 주지 않는다. 시킬 일: "이 주장이 틀린 근거를 코드에서 찾아라. 빈도가 더 낮은 이유, N 상한이 더 작은 이유, 비용을 막는 상한이나 캐시, 측정이 실제 부하가 아닌 이유." 근거가 `파일:줄`로 성립하면 기각한다. 후보가 여럿이면 함께 띄운다.
7. **고치기**: 남은 결함만, 비용을 옮기기보다 없애는 쪽(없애기 → 줄이기 → 틱 밖으로 옮기기 → 여러 틱에 나누기)으로 구조를 고친다.
   - 안전성을 깨지 않는다(CLAUDE.md 2절 우선순위). 병렬로 옮기면 결과 순서와 부동소수 합을 확인하고 결정성 시험(CPU 풀 1개와 여러 개)을 돌린다. 캐시와 색인은 해제 시점과 상한을 같이 둔다.
   - 같은 조건으로 다시 측정한다. 개선이 측정 잡음 안이면 수정을 되돌리고 기각한다.
   - 수정이 공개 API, 저장 형식, 설정 키, 기능 범위를 바꾸면 고치기 전에 묻는다.
8. **검사**: `cargo xtask check`.

감사를 처음부터 되풀이하지 않는다. 고친 자리 주변에서 같은 원인이 새로 보이면 그것만 같은 순서로 다룬다.

## 보고
쉬운 한국어로 짧게.

1. 첫 줄: 고친 결함 N건(치명 a, 중대 b), 미확정 N건, 경미 N건, 기각 N건.
2. 고친 결함마다:
   - `[등급] 한 줄 요약` — `파일:줄`
   - 빈도와 상한 N(근거)
   - 비용: 고치기 전 식과 측정값
   - 증거: 시험이나 측정 이름, 전후 숫자
   - 수정: 근본 원인 한 줄, 고친 뒤 측정값
3. 미확정: 한 줄씩. 무엇이 증명되지 않았고 무엇을 하면 확정되는지.
4. 경미: 한 줄씩. 고치지 않았다.
5. 기각: 이유별 개수만(상한이나 캐시가 막음, 빈도 낮음, 측정이 문턱 아래, 설계로 정함, lint가 막음, 독립 검토가 반박).
6. `cargo xtask check` 마지막 줄, 바뀐 공개 API와 동작.
