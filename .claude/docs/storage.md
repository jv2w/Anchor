# 저장

Anchor가 디스크에 무엇을 어떤 형식으로 쓰고, 언제 커밋하며, 끊겼을 때 무엇을 보장하는지 적는다. 설정 키는 `config.md`, 입력 로그와 재생의 구조는 `architecture.md`, redb 사본과 고친 결함은 `dependencies.md`, 가져오기의 블록 업그레이드 스키마는 `data.md`에 있다.

## 데이터 폴더

기본 폴더는 실행 폴더의 `data/`다(`ServerBuilder::data_dir`로 바꾼다). 서버 실행 폴더에는 `anchor.toml`과 `data/`만 생긴다.

| 경로 | 내용 |
|---|---|
| `data/main.redb` | 저장 차례(엔진 틱과 커밋 식별자). 한 저장에서 마지막으로 커밋한다 |
| `data/players.redb` | 플레이어 데이터. 키는 XUID 10진 문자열, Xbox 로그인을 안 한 플레이어는 `offline:` + 소문자 이름 |
| `data/access.redb` | op, 밴(이름, IP), 화이트리스트. 명령으로 바뀌는 운영 기록이라 설정이 아니라 데이터다 |
| `data/user.redb` | 사용자 프로그램이 등록한 이름별 서버 데이터 |
| `data/world/<월드>.redb` | 영구 월드 하나: 월드 기록과 그 월드의 모든 청크(지형, 블록 엔티티, 엔티티, 예약된 블록 갱신) |
| `data/packs/` | 리소스팩 파일. `resource-packs`의 상대 경로 기준 |
| `data/identity.key` | NetherNet 서버 신원 키(`network.md`) |
| `data/auth.json` | Xbox 인증 문서 캐시(`network.md`) |
| `data/backups/` | 백업. 파일마다 `backups/<파일>/`, 월드는 `backups/world/<월드>/` |
| `data/crash/` | 틱 패닉이나 저장 실패로 멈출 때 쓰는 입력 로그 `input-<유닉스 초>-<틱>.log` |

- 임시 월드(`Kind::Temporary`)는 파일이 없고 저장하지 않는다.
- 월드 이름이 곧 파일 이름이다. 이름 규칙(`world::Error::InvalidName`)은 Windows와 Linux 둘 다에서 파일 이름이 되는 것이다: 1~250바이트, 제어 문자와 `< > : " / \ | ? *` 없음, 끝의 점·공백과 앞의 공백 없음, Windows 장치 이름(`CON`, `PRN`, `AUX`, `NUL`, `CONIN$`, `CONOUT$`, `COM0`~`COM9`, `LPT0`~`LPT9`, 위첨자 숫자 포함, 대소문자와 확장자 무관) 아님. 대소문자만 다른 이름은 한 월드다(Windows가 한 파일로 보므로). `create_world`, `build()`, 가져오기가 같은 규칙을 쓴다.
- 시작은 `data/world/`의 `*.redb`를 이름 순으로 나열해, 선언하지 않은 월드도 틱이 `load_world`로 올릴 수 있게 한다. 규칙에 맞지 않거나 대소문자만 다른 두 번째 파일은 경고하고 뺀다. 실행 중에 넣은 파일은 다음 시작부터 보인다.
- `Context::delete_world`는 로드되지 않은 영구 월드의 파일 하나만 지운다. 앞서 요청된 저장이 끝난 뒤 저장 스레드가 지우고, 백업 폴더는 남긴다.
- 파일마다 따로 두는 이유: 월드 파일 크기가 그 월드의 데이터만큼이고, 바뀌지 않은 파일은 저장에서 쓰지 않으며, 월드 하나를 파일째 지우거나 옮길 수 있다.

## 파일 형식

모든 데이터 파일은 redb 데이터베이스다. 표 이름은 모든 파일에서 같고(`meta`, `worlds`, `chunks`, `players`, `access`, `user`) 파일마다 자기 몫의 표만 채운다. 키와 값은 모두 바이트다.

| 표 | 키 | 값 |
|---|---|---|
| `meta` | `meta` | 그 파일이 마지막으로 받은 저장 차례: 엔진 틱 u64 + 커밋 식별자 |
| `meta` | `closed` | 정상 종료 표시(빈 값) |
| `meta` | `moved` | 옛 단일 서버 파일에서 옮긴 파일의 표시(원본의 meta 값) |
| `worlds` | `world` | 월드 기록: 월드 번호 u32 + 월드 시각 i64 |
| `chunks` | 13바이트 이상(아래) | 서브청크 지형, 엑스트라 목록 쪽 |
| `players` | 플레이어 키 | 월드 이름, 위치 f64 셋, `extra` NBT(인벤토리, 게임 모드 등 규칙 모듈의 상태) |
| `access` | 종류 바이트(0 op, 1 밴, 2 IP 밴, 3 화이트리스트) + 소문자 이름 또는 IP 문자열 | 표시 또는 밴 기록(사유, 출처, 만든 시각, 끝나는 시각) |
| `user` | 등록 이름 | JSON 텍스트 |

청크 키는 월드 번호 u32, x i32, z i32를 빅엔디안으로 쓰고 좌표의 부호 비트를 뒤집은 12바이트 접두(키가 좌표 순으로 정렬된다)와 종류 바이트다.

- `0x20 | 번호`(번호 0 = y -64 ~ 23): 서브청크 하나의 지형. 블록 엔티티가 없는 plains 서브청크가 비어 있으면 값을 쓰지 않고, 읽을 때 빈 서브청크로 본다. 모든 서브청크가 비어 있는 청크만 가장 아래 값을 남겨 생성기가 다시 채우지 않게 한다.
- 1 블록 엔티티, 2 엔티티, 3 예약된 블록 갱신: 엑스트라 목록. 16 MiB 이하 쪽으로 나누고, 쪽 0은 13바이트 키, 쪽 1부터 빅엔디안 u16 쪽 번호를 붙인다.
- 0: 형식 1~3의 통째 지형. 읽기만 하고, 그 청크의 지형을 처음 다시 쓰는 커밋이 24개 서브청크를 모두 쓰고 같은 트랜잭션에서 지운다.

월드 번호는 그 파일 안에서만 쓰인다. 블록은 Bedrock 디스크 팔레트 모양 NBT `{name, states, version}`로만 쓰고 런타임 ID는 쓰지 않는다. 그래서 Anchor가 모르는 블록도 NBT 그대로 왕복한다. 생성된 뒤 바뀌지 않은 청크는 저장하지 않고 생성기가 다시 만든다(생성기를 바꾸면 그런 청크도 바뀐다).

### 봉인

모든 값은 12바이트 머리 + 본문이다(리틀엔디안).

| 바이트 | 내용 |
|---|---|
| 0~1 | 형식 버전 u16 |
| 2 | 압축 방식: 0 그대로, 1 Snappy(형식 8까지), 2 raw DEFLATE |
| 3 | 예약(0) |
| 4~7 | 압축 전 레코드 길이 u32 |
| 8~11 | CRC-32C: 키, 머리 앞 8바이트, 본문을 덮는다 |

- 읽기는 버전 → 체크섬 → 압축 해제 순이다. 버전이 앞 두 바이트라 더 새 값과 손상된 값을 구별한다. 체크섬에 키를 넣어 값이 다른 키 자리로 옮겨진 것도 잡는다.
- 레코드 상한은 압축 전 16 MiB다. 가장 큰 서브청크 값(커스텀 상태 4096개)이 약 9.4 MB라 서브청크마다 값 하나로 나누면 늘 상한 안이다. 디코더가 할당할 수 있는 양은 레코드의 4배(64 MiB)다.
- 64바이트 미만 레코드는 압축하지 않는다. 압축은 libdeflate 6단계다. 실제 가져온 월드에서 Snappy보다 약 3분의 1 작고, 9·12단계는 1.2%·4.1% 더 작지만 느리다.
- 디스크 값도 외부 입력이다: 길이와 개수는 할당 전에 상한을 검사하고, 팔레트 색인은 팔레트 안이어야 하며, 값은 레코드 끝에서 정확히 끝나야 한다. redb 읽기는 페이지 체크섬을 확인하지 않아서 값마다 자체 체크섬을 둔다.

### 형식 버전

지금 쓰는 형식은 9다(`storage::seal::FORMAT_VERSION`). 값마다 자기 형식 번호를 지니고, 다시 쓰일 때 현재 형식이 된다. 1부터 9까지 모두 읽는다.

| 형식 | 그 형식부터 달라진 레이아웃 |
|---|---|
| 1 | 플레이어 위치 f32 셋, `extra` 없음. 지형은 청크 통째 값 하나 |
| 2 | 플레이어 위치 f64와 `extra`, 엑스트라 종류 1~3 |
| 3 | 월드 기록에 시각 |
| 4 | 지형을 서브청크마다 값 하나로, 엑스트라 목록을 쪽으로 |
| 5, 6 | 월드 기록에 시간 정지, 난이도, 날씨(읽을 때 건너뜀) |
| 7 | meta에 커밋 식별자 |
| 8 | 월드 기록이 번호와 시각뿐. 7 이하의 설정 값은 검사 없이 건너뛰고 버린다 |
| 9 | Snappy 대신 raw DEFLATE, 빈 plains 서브청크 값 없음 |

파일의 meta 값 형식이 현재보다 새것이면 시작을 거부한다(`NewerFormat`). 옛 Anchor가 새 파일을 잘못 읽어 덮어쓰지 않게 하기 위해서다.

## 저장 주기와 커밋

게임 상태는 틱 스레드만 바꾸고, 디스크는 저장 스레드(`anchor-save`) 하나만 만진다. 틱은 디스크를 기다리지 않는다.

1. 스냅샷: 틱 경계에서 지난 스냅샷 뒤에 바뀐 것(바뀐 서브청크 `Arc`, 엑스트라, 월드 기록, 플레이어 데이터, access와 user의 바뀐 항목, meta)을 떼어 저장 스레드 큐에 넘긴다. 서브청크는 COW라 틱이 그 뒤 쓰면 그 서브청크만 한 번 복사된다.
2. 스냅샷을 뜨는 때: `save-interval-minutes`마다(`/save-off`로 끔), `Context::save`와 `/save-all`, 관리 명령(op, ban 등), 커밋을 기다리며 내린 청크나 나간 플레이어가 4096개를 넘을 때, 지난 커밋 뒤 입력 로그가 상한(64 MiB)의 4분의 1에 닿을 때, 정상 종료. 뒤의 셋은 메모리 상한이라 자동 저장을 꺼도 뜬다. 앞 스냅샷이 아직 커밋 중이면 다음 틱 경계로 미룬다.
3. 커밋(`save::commit`): 한 스냅샷을 바뀐 파일마다 쓰기 트랜잭션 하나로, 월드 파일들 → players → access → user → main 순서로 커밋한다. 쓰는 파일마다 그 스냅샷의 meta 값을 같이 쓴다. 바뀌지 않은 파일은 쓰지 않고, 월드 기록은 시각이 바뀔 때만 쓴다. 봉인과 압축은 CPU 풀에서 병렬로 한다. 모든 쓰기 트랜잭션은 redb quick repair를 켠다.
4. 커밋이 끝났다는 답은 다음 틱의 입력이다. 틱은 그 답을 받기 전까지 스냅샷에 든 청크와 플레이어 데이터를 메모리에 둔다. 그래서 내린 청크를 다시 읽을 때는 메모리에서 가져오고, 디스크 읽기는 늘 가장 새 커밋을 본다.

이벤트마다 일부만 따로 쓰는 경로는 없다. 퇴장, 청크 내리기, 월드 내리기는 메모리에 두었다가 다음 스냅샷이 함께 쓴다. 한 파일이 다른 파일과 다른 순간의 상태를 담지 않게 하기 위해서다.

값은 절대값이라 같은 커밋을 다시 해도 결과가 같다(멱등). 커밋이 실패하면 핸들을 다시 열어 3번까지 다시 시도한다. 그래도 실패하면 틱이 멈추고 모든 플레이어를 내보내고, 마지막 커밋 뒤의 입력 로그를 `data/crash/`에 쓰고, `Error::Storage`로 끝난다. 실패한 커밋 뒤의 스냅샷은 커밋하지 않는다: 실패한 변경이 빠진 상태를 쓰게 되기 때문이다. 청크 묶음 읽기의 I/O 실패도 같은 재시도 뒤 같은 방식으로 저장 없이 멈춘다.

읽기: 청크와 플레이어 데이터는 틱이 상한 있는 요청으로 보내고, 저장 스레드가 읽기 트랜잭션 하나로 한 청크의 값을 모두 읽은 뒤 디코드와 생성을 CPU 풀에서 한다. 결과는 다음 틱의 입력이다.

손상: 값 하나라도 체크섬이나 디코드에 실패한 청크는 격리한다(빈 청크로 보이고, 바꿀 수 없고, 저장하지 않으며, 디스크 값은 그대로 둔다). 플레이어 데이터가 손상이면 그 플레이어의 접속을 거부하고 데이터는 그대로 둔다. 자동 복원은 하지 않는다.

## 정상 종료와 크래시

정상 종료(Ctrl+C, 콘솔 `stop`, `ShutdownHandle`, Unix SIGTERM·SIGHUP, Windows Ctrl+Break·창 닫기·로그오프·시스템 종료)는 마지막 틱 경계의 스냅샷을 모든 파일에 커밋하고, 진행 중인 백업을 마치고, 열린 파일마다 정상 종료 표시를 커밋한 뒤 끝난다. 복제와 손실이 없다. 종료는 바뀐 파일만 쓰고 compact하지 않아서 1초 안에 끝난다. Windows 창 닫기는 OS가 약 5초만 허락한다. 두 번째 인터럽트는 즉시 끝낸다(종료 코드 130). 이때는 크래시와 같은 보장을 받는다.

크래시(프로세스 강제 종료, 전원 차단, 틱이나 저장 스레드 패닉):

- 한 파일 안의 커밋은 redb 트랜잭션이라 통째로 들어가거나 안 들어간다. 다음 열기에서 redb가 복구한다.
- 마지막 커밋 뒤의 변경은 잃는다(최대 저장 주기 하나).
- 크래시가 한 저장의 파일 사이에 오면 앞 파일은 새 차례, 뒤 파일은 앞 차례로 남는다. main이 마지막이므로 이때는 늘 어떤 파일이 main보다 뒤 차례를 가진다. 시작이 파일마다 meta를 main과 비교해 더 뒤인 파일(틱이 크거나, 같은 틱에 다른 커밋 식별자)을 error로 남긴다: 파일 이름, 그 파일의 저장 틱, main의 저장 틱, 아이템이 겹치거나 사라졌을 수 있다는 문장. 실행 중 처음 여는 월드 파일도 같은 비교를 한다. 뒤처진 파일은 정상이다(바뀌지 않아 쓰지 않은 파일).
- 확정적으로 복제가 나는 경로는 없다. 한 블록이나 한 플레이어의 데이터는 한 파일에 있어 그 파일 안에서는 늘 하나다.
- 틱이나 저장 스레드가 패닉하면 저장 스레드는 큐에 남은 스냅샷을 커밋하지 않고 닫는다. 패닉 직전 상태는 믿을 수 없기 때문이다. 입력 로그는 `data/crash/`에 남는다. 정상 종료 표시는 남지 않는다.

여러 파일을 묶는 저널이나, 마지막으로 모두 일치한 차례로 되돌리기(redb 지속 세이브포인트)는 하지 않는다. 세이브포인트가 쥔 페이지는 다시 쓰이지 않아 파일이 바뀐 데이터만큼 커지고, 되돌리면 앞서 커밋된 파일의 정상 데이터도 잃는다. 대신 어긋남을 크게 알리고 원본을 그대로 둔다.

남은 위험:

- 파일 사이 크래시 뒤에는 아이템이 겹치거나 사라질 수 있다. 시작 로그의 error가 그 경우를 알린다.
- 사용자 콜백이 외부 시스템(파일, 네트워크)에 한 일은 크래시로 되돌아가지 않는다.
- redb가 고치지 않은 결함: 체크섬까지 맞춘 조작 파일은 큰 할당을 일으킬 수 있고, 실행 중 하드웨어가 만든 페이지 손상은 읽기 패닉이 되어 저장 없이 멈춘다(다음 시작의 검사가 거부한다). `dependencies.md`에 있다.
- `integrity-check = "never"`면 시작이 손상을 찾지 않는다.

## 시작과 무결성 검사

시작은 파일마다(`Storage::open`) 다음을 한다.

1. 닫힌 파일을 배타 잠금 아래 복사한다. 잠금이 실패하면 다른 프로세스가 연 파일이라 `InUse`로 거부한다. 복사는 `backups = true`면 백업이 되고, `false`면 검사하는 시작에서만 임시 사본으로 만든다.
2. 연다. 크래시가 남긴 파일은 redb가 여기서 복구한다.
3. `integrity-check`대로 redb `check_integrity()`를 한다: `always`는 늘, `after-unclean-shutdown`은 정상 종료 표시가 없을 때만, `never`는 하지 않는다. 표시는 정상 종료의 마지막 커밋이 쓰고 시작의 첫 커밋이 지운다. 표시는 쓰기 없는 읽기 전용 열기로 읽고, 그렇게 열 수 없는 파일은 표시 없음으로 보아 검사한다.
4. redb가 제자리에서 고친 것(`Ok(false)`)도 손상이다. 손상이거나 더 새 형식이면 시작을 거부하고, 사본을 파일에 다시 써 시작 전 바이트 그대로 둔다. 열기와 검사가 파일을 쓸 수 있어서 사본이 원본을 지킨다.
5. 첫 커밋으로 없는 표를 만들고 정상 종료 표시를 지운다.

시작은 compact하지 않는다. COW로 풀린 페이지는 다음 커밋이 다시 쓰고, 빈 끝은 데이터가 줄 때만 생기는데 Anchor는 청크를 지우지 않으며 월드 지우기는 파일째 지운다.

시작에 여는 파일은 main, players, access, user, 선언된 영구 월드다. 나머지 월드 파일은 처음 열 때 같은 절차를 밟는다. 월드 파일이 열리지 않으면 그 월드의 청크를 모두 격리하고 저장하지 않는다.

시작 비용은 `integrity-check`와 `backups`가 정한다. 381 MB 데이터 파일에서 `backups = false`, `after-unclean-shutdown`의 정상 종료 뒤 시작은 0.1초 미만이고, `always`는 파일을 디스크에서 모두 읽어 5.6~16.4초다.

실행 중 검사 `/check`(op, 권한 `anchor.command.check`, 게임과 콘솔): 다음 스냅샷이 커밋된 뒤 열린 파일마다 그 커밋의 읽기 트랜잭션 하나로 모든 값을 8 MiB 단계씩 읽어 봉인(머리와 CRC-32C)을 확인한다. 압축 해제와 디코드는 하지 않는다. 단계 사이에 밀린 요청을 먼저 처리해 틱이 기다리지 않는다. 한 번에 하나만 돈다. 결과(통과한 값 수, 손상 수, 첫 손상의 파일과 표)는 요청자에게 가고 로그와 입력 로그에 남는다. 실행 중에 redb `check_integrity()`를 쓰지 않는 이유는 닫힌 파일이 필요하고 손상을 고치면서 파일을 덮어쓰기 때문이다(손상된 데이터는 덮어쓰지 않는다).

## 백업

- 위치와 이름: `data/backups/<파일>/<유닉스 초>[-n].redb`, 월드는 `data/backups/world/<월드>/`. 같은 초의 두 번째 백업은 `-n`을 붙이고, 시계가 뒤로 가도 이름은 가장 새 초를 이어 간다. 그래서 이름 순서가 곧 시간 순서다.
- 파일마다 최근 3개를 남긴다(시작 백업과 실행 중 백업을 함께 센다). 백업은 덮어쓰지 않는다. 디스크는 파일 크기의 최대 3배를 더 쓴다.
- 시작 백업: 위 시작 1번의 복사. `<이름>.tmp`로 쓰고 동기화한 뒤 이름을 바꾼다. 잘린 복사가 백업으로 세어져 좋은 백업을 밀어내지 않게 하기 위해서다. 시작은 끊긴 실행이 남긴 `.tmp`를 지운다. 오래된 백업 정리는 성공한 시작 뒤에만 한다. 손상으로 거부된 시작의 사본은 백업으로 세지 않는다.
- 실행 중 백업(`Context::backup`, 명령 `backup`(op)): 다음 스냅샷이 커밋된 뒤 열린 모든 파일을 그 커밋의 읽기 트랜잭션 하나에서 8 MiB 단계씩 `.tmp`로 복사한다. 단계 사이에 다른 요청을 처리한다. 단계 커밋은 동기화하지 않고, 다 복사하면 지속 커밋 한 번, 닫기, 동기화, 이름 바꾸기로 마친다. 실패하면 `.tmp`를 지우고 error를 남기며 서버는 계속 돈다. 이미 백업 중이면 새 요청은 거부한다. 정상 종료는 진행 중 백업을 마친 뒤 닫는다.
- `backups = false`면 시작 백업을 만들지 않고 `Context::backup`은 `false`를 돌려준다.
- 되돌리기는 자동으로 하지 않는다. 운영자가 서버를 멈추고 같은 백업 차례의 파일들을 함께 제자리에 복사한다.

## 재생과 데이터 파일

`Server::replay(log)`는 `data/crash/`의 입력 로그를 다시 돌린다(구조는 `architecture.md`). 데이터 파일은 읽기 전용으로만 연다: main의 사본(파일, 백업 새것부터) 중 로그 구간의 저장 차례(틱과 커밋 식별자)와 같은 것을 고르고, 다른 파일은 그 차례 또는 그 앞에 커밋된 사본 중 가장 새것을 쓴다. 파일마다 바뀔 때만 쓰기 때문이다. 맞지 않는 사본이면 청크 체크섬 대조가 어긋남을 잡는다. 재생은 아무것도 커밋하지 않고 파일을 쓰지 않는다.

크래시 로그는 64 MiB 입력 상한과 1 GiB 파일 상한 안에서 쓴다. 로그 형식 번호는 저장 형식과 따로 있다.

## 형식 바꾸기

1. `storage::seal::FORMAT_VERSION`을 올리고, 그 상수의 문서와 이 문서의 형식 표에 새 레이아웃을 적는다.
2. 레코드 디코더(`storage::codec`)는 값의 형식 번호로 레이아웃을 고른다. 이전 형식은 모두 계속 읽는다. 없어진 필드는 건너뛰고, 새 필드는 그 필드가 없던 때의 동작을 뜻하는 값으로 채운다.
3. 값은 다시 쓰일 때 새 형식이 된다. 키 구조가 바뀌면(통째 지형 → 서브청크) 새 키를 쓰는 커밋이 같은 트랜잭션에서 옛 키를 지운다.
4. 파일 구조 자체가 바뀌면 시작 전에 옮기기를 둔다(아래). 원본은 쓰지 않고, 끊겨도 다음 시작이 다시 할 수 있어야 한다.
5. 시험: 새 형식 왕복, 옛 형식 값과 파일을 읽어 같은 상태가 되는지, 더 새 형식이 거부되고 파일이 그대로인지, 깨진 값에서 패닉이 없는지.

옛 단일 서버 파일 옮기기(`save::migrate`): `main.redb`가 없고 `data/server.redb`(또는 더 옛 이름 `world.redb`)가 있으면 시작과 가져오기가 먼저 한다. 배타 잠금 아래 `data/moving/`에 복사하고, 사본을 `check_integrity()`로 검사하고(손상이면 시작 실패), 모든 값을 현재 형식으로 다시 써 새 파일마다 트랜잭션 하나로 커밋하고(읽히지 않는 값은 그대로 복사해 격리를 유지), 파일마다 compact 한 번과 정상 종료 표시를 쓴 뒤, 다시 열어 검사하고 값 개수를 원본과 대조한다. 그다음 파일들을 옮기고 main을 마지막에 옮긴 뒤 원본과 `moving/`을 지운다. 실패하면 원본 그대로 시작이 멈춘다. 도중에 끊기면 main이 없으므로 다음 시작이 다시 하고, 이미 옮겨진 파일은 이 옮기기가 쓴 것(`moved` 표시가 원본 meta와 같음)일 때만 덮는다. 원본의 백업(`data/backups/server-*.redb`)은 그대로 둔다. 디스크는 원본, 사본, 새 파일만큼 잠깐 필요하다.

## 월드 가져오기

`Server::import_world(폴더, 이름)`은 `run` 전에 Bedrock(LevelDB) 월드 폴더를 새 파일 `data/world/<이름>.redb` 하나로 가져온다. 다른 파일은 쓰지 않는다.

- 원본은 읽기만 한다. LevelDB 리더는 Anchor가 직접 쓴 읽기 전용 리더라 `LOCK`, 로그 재생, compaction을 원본에 쓰지 않는다. 가져오는 동안 원본 파일이 바뀌면 실패한다(다른 프로그램이 연 월드).
- 오버월드의 블록과 블록 엔티티(NBT 전부: 상자 안 아이템, 간판 글자 등)와 `level.dat`의 시각만 가져온다. 옛 블록 상태와 아이템은 PMMP처럼 업그레이드하고, 모르는 블록은 알 수 없는 블록으로 NBT를 보존한다. 바이옴은 월드 생성기가 주는 값이다. 엔티티, 바이옴, 예약 갱신, 네더와 엔드, 플레이어는 가져오지 않고 세어 `import::Report`에 적는다.
- `level.dat`의 설정(시드, 게임 모드, 난이도, 게임 규칙)은 가져오지 않는다. 스폰은 쓰지 않고 `Report::spawn`으로 알려 `[worlds.<이름>] spawn`에 옮겨 적게 한다.
- 청크는 저장 스레드와 같은 변환과 봉인을 거쳐 Anchor가 스스로 쓰는 바이트와 같다. 모두 공기인 청크도 쓴다(안 쓰면 생성기가 채운다). 스레드 수와 상관없이 같은 원본은 같은 바이트가 된다.
- 쓰기 트랜잭션 하나로 커밋한다. 청크 하나라도 실패하면 파일을 남기지 않고, 오류는 원인 청크와 키를 보인다. 같은 이름(대소문자 무관)의 파일이 있으면 `WorldExists`로 거부하고 아무것도 바꾸지 않는다. 임시로 선언된 이름은 거부한다. 선언하지 않은 이름은 기본 월드의 생성기를 쓰고 틱이 `load_world`로 올린다.

## 저장하지 않는 것

설정은 저장하지 않는다. 매 시작의 설정은 `anchor.toml`과 코드(`ServerBuilder`, 실행 중 만든 월드는 `world::Options`)에서만 온다. 데이터 파일과 설정이 서로 다른 값을 가져 어느 쪽이 이기는지 헷갈리는 일이 없고, 설정을 바꾸면 다음 시작에 그대로 적용된다.

- 그래서 실행 중 API로 바꾼 서버·월드 난이도, 월드 스폰, 시간 정지, 날씨, 게임 규칙은 다시 켜면 설정 값으로 돌아간다. 날씨는 맑음, 시간 정지는 꺼짐으로 시작한다.
- 시드는 `level-seed`가 비면 월드 이름의 SHA-256 앞 8바이트다. 시작마다 같고 월드마다 다르다.
- 월드 파일에는 상태만 남는다: 번호, 시각, 청크. 시각은 이어지고 낮밤 순환은 그 시각에서 계속된다.
- `save-player-data = false`면 플레이어 데이터를 저장하지 않는다.
